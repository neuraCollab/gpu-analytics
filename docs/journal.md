## Неделя 1 (10–15.11.2026)
- **Сделано:** каркас репозитория, проверка окружения, генерация TPC-H, запросы Q1 и Q6, движки DuckDB / Polars CPU / Polars GPU, протокол замеров, сверка ответов, тесты.
- **Измерено** (ноутбук: Intel, 8 физических ядер, 15.7 GB RAM, без GPU; TPC-H SF1, медиана 5 запусков):

  | Движок | Q1 | Q6 |
  |---|---|---|
  | DuckDB | 0.070 с | 0.035 с |
  | Polars CPU | 0.055 с | 0.030 с |

  Ответы Polars CPU совпали с DuckDB. Генерация SF1 заняла 7 с; `lineitem` — 189 MB в Parquet.
- **Проблемы:**
  - `uv` не смог скачать Python 3.12 на Windows (ошибка симлинка), окружение создано на системном Python 3.14.
  - В DuckDB 2.0 у соединения нет метода `.pl()` — используется `con.sql(...).pl()`.
  - Консоль Windows в cp1251 — вывод переключён на UTF-8.
- **Дальше:** проверить GPU-путь в Colab или на ЕВК; добавить остальные 20 запросов из polars-benchmark; CPU-базисы на SF10.

## Неделя 2 (10.11.2026, начало)
- **Сделано:** все 22 запроса TPC-H в двух видах (SQL и Polars), каждый в отдельном файле `queries/tpch/qNN.py`. Polars-версии написаны по мотивам pola-rs/polars-benchmark, но с точной семантикой SQL (например, Q21 через число уникальных поставщиков в заказе, а не через число позиций).
- **Проверено:**
  - Polars CPU совпадает с DuckDB на всех 22 запросах, на SF 0.01 и на SF1.
  - Ответы DuckDB на SF1 совпадают с официальными ответами TPC-H (Q4, Q6, Q14, Q15, Q17, Q19, Q22 сверены вручную).
- **Измерено** (тот же ноутбук, SF1, медиана 5 запусков), секунды:

  На SF1 всё укладывается в десятые доли секунды, поэтому для выводов о GPU нужны SF10 и больше.
- **Находки:**
  - Сумма пустого набора: в SQL `SUM` даёт NULL, в Polars `sum()` — 0. На SF 0.01 из-за этого разошёлся Q17 (фильтр не нашёл ни одной строки). Добавлена функция `sql_sum`; она используется в Q6, Q14, Q17 и Q19. Это пример того, почему сверка ответов обязательна: «быстрее, но другой ответ» не считается ускорением.
  - Q15 в DuckDB написан через `WITH … AS MATERIALIZED`. Иначе выручка может посчитаться дважды с разным порядком сложения, и тогда равенство с максимумом не выполнится.
  - Q11: порог 0.0001 взят без деления на SF (это допустимо для сравнения движков, отмечено в файле запроса).
- **Дальше:** GPU-прогон всех 22 запросов (Colab/ЕВК), чтобы выяснить, какие из них Polars GPU не поддерживает (результат способа 1); CPU-базисы на SF10.
